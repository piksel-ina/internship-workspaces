# Contributing

## Program boundaries

Keep work for each program inside its directory under `programmes/`.

## Branches and pull requests

Do not push directly to `main`.

Create a branch for each piece of work and open a pull request when it is ready for review. Keep each pull request focused on one related change.

Use a short title that describes the change. In the pull request body, explain what changed and why, link a related GitHub Issue when there is one, and add any context a reviewer needs.

When a pull request is ready, request a review from a mentor.

## Language

Use English for shared repository documents and pull requests.

Daily logs and weekly recaps may use Bahasa Indonesia.

Use English for technical terms. This includes Git and GitHub terms such as branch, commit, pull request, review, and merge.

## Sensitive information

Do not add credentials, access tokens, or other sensitive information to the repository.
